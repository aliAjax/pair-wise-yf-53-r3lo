# pair-wise-yf-53 开源项目发布列车准备和门禁控制台

## 源提示词摘要
维护者创建跨仓库发布，关联版本、负责人、阻断问题和待合并依赖，安排冻结时间与分批顺序。发布前检查依赖、阻断、超时确认和顺序冲突，支持冻结、降级、回滚准备状态及可追溯审计。

## 技术栈
React Router 7 框架模式 + TypeScript + Mantine + Redux Toolkit + RTK Query + React Hook Form + Zod + Lingui + dnd-kit + Vitest。

## 可重算排程闭环
- **发布列车 / 仓库门禁 / 分批计划一份数据**：仓库依赖（`dependsOn`）构成依赖图，Kahn 分层自动产生批次（`app/lib/schedule.ts`），不再手动跨批拖拽。
- **变更即重算**：依赖、负责人或确认状态保存后重算每批仓库；同层沿用上一次排列，因此「仍在本批的确认按新顺序保留」。
- **已交付不倒回**：`delivered` 批次整体冻结，成员、顺序、确认时间锁定；重算只作用于未处理仓库（已交付的依赖视为已可用）。
- **批次内拖拽**：dnd-kit 排序仅限当前批次，跨批顺序由依赖决定；拖拽会同步稳定排序，后续重算保留。
- **两人同改一个仓库（乐观锁）**：每个门禁带 `rev`，写入必须带读取时的 `expectedRev`；先写入者生效，后到者被拒，并看到受影响的未交付下游仓库（反向依赖闭包），刷新到最新版本后才能再改。
- **远端依赖查询容错**：RTK Query 轮询健康检查。失败时保留上一次可发布批次快照并暂停重算（编辑只标记 dirty）；恢复后沿用快照，只重算未处理仓库。页面提供「模拟故障 / 恢复查询」开关。
- **放行门禁**：当前批次门禁全部确认、无未关闭关键阻断、远端可达、列车处于 preparing 才允许交付；依赖环不会冻结整列车，环上仓库沉入末批并在界面与审计中标注。
- 阻断关闭、冻结/回滚、审计历史、旧版 localStorage 数据（`dependency` 字符串）自动迁移。

## 启动
```bash
npm install
npm run dev      # 开发端口 62018
npm test         # 排程算法 + store 流程测试（15 个用例）
npm run build    # 生产构建 + tsc 类型检查
```

## 关键文件
- `app/lib/schedule.ts`：拓扑分层重算、受影响仓库反查、批次可发布检查（纯函数，可单测）。
- `app/store/index.ts`：批次模型、`rev` 乐观锁与冲突信息、远端故障/恢复状态机、旧数据迁移。
- `app/routes/home.tsx`：批次看板、门禁编辑弹窗（身份选择 + 版本提示）、故障降级横幅、冲突提示。
